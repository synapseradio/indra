## Why

The offline test suite resolves cross-package `@indra/runtime-*` imports through a
single root alias map in `vitest.shared.ts`, hand-built from the package manifest.
It is global — every package's test run is coupled to that one file — and it is a
second copy of a fact the tsconfigs already encode. The workspace should give each
package its own self-contained test configuration and let one orchestrator run them,
so tests cache per package and only changed packages rerun.

## What Changes

- Each package owns a self-contained `vitest.config.ts`, generated by the scaffold.
  Cross-package `@indra/runtime-*` specifiers (and the
  `@indra/runtime-core/inference-live` subpath) resolve to source through a
  generated `resolve.alias` map; `~/*` resolves through tsconfig path mappings.
- **BREAKING** (developer-facing only): the root `vitest.shared.ts` and
  `vitest.workspace.ts` are removed. Turbo is the orchestrator.
- `turbo run test` runs each package's tests, caches per package, and reruns only
  changed packages. The `test` task gains a `check:types` / `^check:types`
  dependency, so type-checking completes before tests in every scope. Vite never
  type-checks.
- The `scripts/scaffold/` CLI generates the new shape and always emits a base
  `README.md` for each package, so no package lands without a readme. The manifest
  stays the single edit point.

## Capabilities

### New Capabilities

- `package-scaffold`: what the scaffold CLI produces for each package — the
  generated file set, the base README, the self-contained nested test
  configuration, how the offline suite resolves modules, and how turbo orchestrates
  and gates the suite.

## Impact

- `scripts/scaffold/parts.ts` (the `vitestConfig`, tsconfig, and a new `readme`
  generator) and `scripts/scaffold/manifest.ts` if a per-package description is
  needed.
- Each package's generated `vitest.config.ts`, `README.md`; removal of root
  `vitest.shared.ts` and `vitest.workspace.ts`; `turbo.json` `test` task.
- No runtime source changes and no change to `tsc -b` behavior; the offline test
  suite must stay green.
